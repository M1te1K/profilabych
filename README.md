# Профилабыч

Модульный AI-агент для будущего Telegram-бота. **Этап 2 реализован:** ядро,
OpenRouter Chat Completions, Tool Calling, калькулятор, время, заметки, SQLite,
история и локальный CLI. Ядро не зависит от aiogram или httpx. Telegram polling,
RAG, PDF, дополнительные AI-агенты, голос и деплой в этот этап не входят.

## Установка

Python 3.12–3.14. Зависимости бесплатные; локальная модель, GPU и сервер БД не нужны.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --require-hashes -r requirements-dev.txt
.venv/bin/python -m pip install --no-deps -e .
```

`requirements.txt` и `requirements-dev.txt` фиксируют версии и хеши. Новых
зависимостей на этапе 2 нет: используются установленные httpx, aiosqlite,
Pydantic 2, pytest и pytest-asyncio. На macOS нужен доступный IANA timezone database
(в проверенном окружении UTC и Europe/Moscow доступны).

## Проверка без API и ключей

```bash
.venv/bin/python -m profilabych --check
.venv/bin/python -m profilabych --demo
```

`--check` проверяет настройки, выводит JSON-событие `infrastructure_ready` с
`stage=2`, не открывает SQLite и не обращается к сети. Это прежний инфраструктурный
режим, теперь с явным флагом.

`--demo` использует настройки по умолчанию, не читает локальный `.env` и переменные
конфигурации. Скриптовая Fake LLM вызывает настоящие инструменты и временную
SQLite. Временные данные удаляются после демонстрации; это отдельный явный режим,
он никогда не используется как fallback настоящего провайдера.

```text
Пользователь: Посчитай 15 * 4 и сохрани результат как заметку
Fake LLM -> calculator: {"expression":"15 * 4"}
calculator -> {"ok":true,"data":{"result":"60"},"error":null}
Fake LLM -> save_note: {"text":"60"}
save_note -> SQLite -> {"ok":true,"data":{"note_id":1},"error":null}
Итог: 15 * 4 = 60. Сохранено как заметка №1.
/reset: история пуста, заметка 60 сохранена.
```

Это подтверждённый офлайн-сценарий. Реальные запросы к OpenRouter на этапе 2
не выполнялись; актуальная доступность Qwen и поведение реальной LLM не подтверждены.

## CLI с OpenRouter

Обычный запуск требует ключ. Эта инструкция предназначена для будущей отдельно
разрешённой проверки API; без ключа CLI выводит понятную ошибку до создания БД.

```bash
cp -n .env.example .env
chmod 600 .env
# Настроить OPENROUTER_API_KEY в локальном .env или окружении.
.venv/bin/python -m profilabych
# Альтернатива: .venv/bin/profilabych
```

CLI принимает сообщения, `/reset` и `/exit`; EOF и Ctrl+C завершают работу.
Логи идут в stderr, ответы и приглашения — в stdout. `/reset` очищает историю
текущего чата, сохраняя заметки. `Agent.reset_history(user_id)` без `chat_id`
очищает всю историю этого пользователя во всех чатах, также сохраняя заметки.

CLI использует локальные `user_id=1`, `chat_id=0`; изменить их можно флагами
`--user-id 42 --chat-id 10`. Эти флаги служат локальной проверке и не являются
аутентификацией. В Telegram идентификаторы обязан передавать адаптер из события.
Не предоставляйте локальный CLI как публичный многопользовательский сервис.

## Конфигурация

Настройки загружаются на старте, без побочных эффектов при импорте. Приоритет:
аргументы `Settings`, окружение, `.env`, значения по умолчанию. Неизвестные поля
в `.env` отклоняются. Реальные секреты никогда не входят в исходники или примеры.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `APP_ENV` | `development` | development/test/production |
| `LOG_LEVEL` | `INFO` | Уровень JSON-логов |
| `DATABASE_PATH` | `data/profilabych.sqlite3` | SQLite, родительский каталог создаётся автоматически |
| `TELEGRAM_BOT_TOKEN` | пусто | Зарезервирован для этапа Telegram |
| `OPENROUTER_API_KEY` | пусто | Обязателен только для обычного CLI |
| `OPENROUTER_BASE_URL` | `https://openrouter.ai/api/v1` | Только официальный HTTPS endpoint |
| `LLM_MODEL` | `qwen/qwen3-coder:free` | Явный бесплатный ID provider/model:free |
| `LLM_TIMEOUT_SECONDS` | `30` | Общий timeout одной HTTP-попытки, до 300 с |
| `LLM_MAX_TOKENS` | `1024` | Лимит ответа модели |
| `LLM_MAX_RETRIES` | `2` | Повторы после первой попытки, 0–3 |
| `LLM_RETRY_DELAY_SECONDS` | `0.5` | Начальный backoff; ожидание ограничено 5 с |
| `AGENT_MAX_TOOL_CALLS` | `5` | Общий предел вызовов за запрос, 1–20 |
| `AGENT_MAX_TOOL_ROUNDS` | `5` | Раунды с инструментами, 1–5 |
| `TOOL_TIMEOUT_SECONDS` | `5` | Timeout отдельного инструмента, до 30 с |
| `TOOL_RESULT_MAX_CHARS` | `8000` | Максимальный JSON результата инструмента |
| `HISTORY_MAX_MESSAGES` | `40` | Лимит сохранённой истории и передаваемой части диалога |
| `HISTORY_MAX_CHARS` | `64000` | Лимит суммарного сериализованного размера сообщений |
| `USER_INPUT_MAX_CHARS` | `4000` | Лимит входного текста |
| `NOTE_MAX_LENGTH` | `2000` | Лимит заметки, допускается уменьшение |

Системный prompt добавляется отдельно к ограниченной истории. Символьный лимит
не является токенизатором конкретной модели. Пределы проверяются также во время
исполнения. Добавлять `user_id` в JSON аргументов заметок запрещено схемой.

## OpenRouter и нулевой бюджет

Перед первым completion адаптер запрашивает `/models`: модель должна присутствовать,
иметь нулевые `prompt`, `completion`, `request` тарифы и поддерживать `tools` и
`tool_choice`. Результат проверки кешируется на срок жизни адаптера. Каждый запрос
передаёт `provider.max_price={prompt:0, completion:0, request:0}`,
`require_parameters=true`, `allow_fallbacks=false`. Платных моделей, списка fallback
и обхода отказа бесплатного endpoint нет.

Формат обмена соответствует [Chat Completions](https://openrouter.ai/docs/api/reference/overview),
[Tool Calling](https://openrouter.ai/docs/guides/features/tool-calling) и
[ограничениям provider routing](https://openrouter.ai/docs/guides/routing/provider-selection#max-price).
Для смены Qwen достаточно изменить `LLM_MODEL` на бесплатную модель с tools;
наличие доступной бесплатной DeepSeek не гарантируется.

Timeout/transport errors, HTTP 429 и 500/502/503/504 повторяются ограниченно;
`Retry-After` (секунды или HTTP-дата) ограничивается 5 с. Остальные HTTP-ошибки,
redirect, некорректный JSON, пустые/повреждённые/обрезанные ответы возвращаются
как контролируемые ошибки. HTTP-клиент закрывается при выходе, ошибке и отмене.
Каталог ограничен 8 МБ, completion — 1 МБ; текст сообщения — 16000 символов.

## Ядро, инструменты и данные

`Agent.handle(user_id, text, chat_id=0)` загружает историю, добавляет запрос и
передаёт LLM сообщения вместе со схемами registry. Все `tool_calls` одного ответа
исполняются последовательно. Каждому соответствует `role=tool` с исходным
`tool_call_id`. Затем модель получает результат и может запросить следующий
инструмент. После лимита разрешён ещё один completion с `tool_choice=none`
для итогового текста; запрос новых инструментов отклоняется без выполнения.

Tool Registry хранит имя, описание, Pydantic-модель аргументов и async-handler;
JSON Schema выводится из той же модели, которая проверяет аргументы. Результат:
`{ok, data, error}`. Для нового инструмента достаточно определить параметры и
handler и зарегистрировать `Tool` в точке сборки; Agent Core не меняется.

| Инструмент | Поведение |
| --- | --- |
| `calculator` | AST whitelist: числа, + − × ÷, скобки, унарные знаки; Decimal, точность 28 цифр; результат строкой |
| `current_time` | datetime/zoneinfo, UTC по умолчанию, ISO 8601 |
| `save_note` | Текст до 2000 символов, возвращает note_id |
| `list_notes` | Только заметки текущего пользователя, по времени создания и ID; limit 1–20, offset |

Калькулятор не использует eval/exec: максимум 256 символов, 64 AST-узла, глубина 16,
модуль каждого числа/результата до 10^15. Очень малые ненулевые результаты (<10^-28)
отклоняются. Деление на ноль и запрещённые конструкции дают понятные ошибки.

SQLite использует aiosqlite, WAL, busy timeout и параметризованные SQL. Заметки
выбираются по `user_id`, история по `(user_id, chat_id)`. Завершённый ход хранится
атомарно в `history_turns`; заметки — в `notes`. Старые ходы удаляются целиком,
без разрыва tool-call/result. Текущий ход не обрезается; до вызова инструмента
резервируется место для результатов и итогового ответа. Слишком большой ход
останавливается контролируемо. Большой list_notes требует меньшего limit/offset.

Запросы и reset одного пользователя сериализуются в одном экземпляре Agent;
разные пользователи могут одновременно ожидать LLM. Ошибки инструмента возвращаются
модели для исправления. При сбое LLM сохраняется завершённый ход с локальным
сообщением об ошибке. При отмене незавершённые call IDs получают результат
`interrupted`, отмена распространяется дальше. Соединение БД закрывается на выходе.

Вызовы инструментов и весь диалог не являются одной транзакцией: заметка может
сохраниться до ошибки LLM/финального коммита истории. Это отражено в ошибке;
повторный запрос способен создать вторую заметку. При аварийном завершении процесса
между сохранением заметки и записью хода история этого хода может отсутствовать.
Многопроцессная сериализация и восстановление после аварии — будущая работа.

## Логирование и проверки

JSON-логи содержат UTC timestamp, user_id/chat_id, request_id, запрос/ответ,
инструмент, аргументы, результат, длительность и код ошибки. По требованию этапа 2
тексты логируются ограниченно: до 1000 символов на строковое поле, 20 элементов
на коллекцию, глубина 6 и общий бюджет обхода. Известные секреты, token/Bearer
patterns и чувствительные ключи маскируются **до** усечения. HTTP и aiosqlite debug
подавлены. Сырые HTTP-тела, заголовки и настройки целиком не логируются.
Логи могут содержать пользовательские данные; доступ к ним должен оставаться
локальным. Маскирование не распознаёт все возможные секреты произвольного текста.

```bash
.venv/bin/python -m pytest
.venv/bin/python -m ruff check .
.venv/bin/python -m ruff format --check .
.venv/bin/python -m mypy src
.venv/bin/python -m pip check
.venv/bin/python -m compileall -q src
```

Тесты используют MockTransport, Fake LLM и временную SQLite, очищают окружение
и запрещают реальные network connect. Проверяются инструменты, ошибки, retry,
лимиты, история/ID/порядок, reset, изоляция, конкурентность, отмена, CLI и секреты.
Результаты и ограничения находятся в [отчёте этапа 2](docs/stage-2-report.md).

## Структура и следующий этап

```text
src/profilabych/
├── main.py                 # сборка зависимостей и режимы запуска
├── config.py / logging.py  # настройки и JSON-логи
├── demo.py                 # офлайн-демонстрация
├── agent/core.py           # диалог и цикл инструментов
├── llm/models.py           # Message, ToolCall, LLMProvider, LLMError
├── llm/openrouter.py       # HTTP, бюджет, retry, нормализация
├── llm/fake.py             # скриптовый провайдер
├── tools/registry.py       # Tool, ToolContext, ToolResult, ToolRegistry
├── tools/calculator.py / current_time.py / notes.py
├── storage/contracts.py / history.py / sqlite.py
└── interfaces/cli.py / telegram/
```
