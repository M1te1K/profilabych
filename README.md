# Профилабыч · v0.1.0

Telegram AI-агент на Python с инструментами, историей диалога и заметками в SQLite.
Модель отвечает через OpenRouter; агент может выполнить вычисление, узнать время,
сохранить заметку и показать сохранённые записи. Есть локальный CLI и офлайн-демо.

Это первая версия для самостоятельного запуска. Публикация исходников не запускает
бота: процесс должен работать на вашем компьютере или сервере. Облачный хостинг
в этот релиз не входит.

## Возможности

- Telegram: личные текстовые сообщения и команды `/start`, `/help`, `/reset`.
- Четыре инструмента: `calculator`, `current_time`, `save_note`, `list_notes`.
- Последовательные вызовы инструментов, лимиты и проверка аргументов.
- История отдельно для каждого пользователя и чата; заметки отдельно для пользователя.
- Московское время по умолчанию, например «Сейчас в Москве 15:12».
  Явно указанный город или часовой пояс имеет приоритет для текущего запроса.
- Даты в SQLite хранятся в UTC, даты заметок показываются в выбранном часовом поясе.
- Безопасное отображение жирного текста и inline code в Telegram; длинные ответы
  разбиваются на сообщения с учётом emoji.
- Бесплатная модель OpenRouter с проверкой тарифа и поддержки Tool Calling.

Фото, PDF, голос, группы, RAG и дополнительные AI-агенты пока не поддерживаются.
Выбор инструмента зависит от модели: ответ реальной LLM не гарантирован тестами.

## Что потребуется

- Git и Python **3.12–3.14**. Основная инструкция ниже — для macOS/Linux.
- Для Telegram: бот от BotFather, ключ OpenRouter и доступ к интернету.
- Для `--check`, `--demo` и тестов API-ключи не нужны. Установка зависимостей
  требует доступа к Python Package Index.
- Доступная база часовых поясов IANA, включая `Europe/Moscow`.
  На macOS она обычно есть; на Linux установите системный пакет `tzdata`, если
  проверка настроек сообщает об отсутствии часового пояса.

Локальная LLM, GPU и отдельный сервер базы данных не нужны.

## 1. Клонирование и установка

```bash
git clone https://github.com/M1te1K/profilabych.git
cd profilabych
git checkout v0.1.0
python3 --version
python3 -m venv .venv
.venv/bin/python -m pip install --require-hashes -r requirements.txt
.venv/bin/python -m pip install --no-deps -e .
```

Перед созданием окружения убедитесь, что `python3 --version` показывает 3.12,
3.13 или 3.14. При нескольких установленных версиях используйте подходящий
интерпретатор, например `python3.13 -m venv .venv`.

`requirements.txt` фиксирует версии и хеши рабочих зависимостей.
`requirements-dev.txt` содержит также инструменты разработки. Установка пакета
в editable-режиме даёт команды `python -m profilabych` и `profilabych`.
Активация окружения необязательна: команды ниже явно используют `.venv`.

## 2. Проверка без ключей

Из корня проекта выполните:

```bash
.venv/bin/python -m profilabych --check
.venv/bin/python -m profilabych --demo
```

`--check` проверяет настройки, выводит событие `infrastructure_ready` и не создаёт
БД. Он не проверяет действительность ключей или доступность внешних сервисов.
`--demo` использует Fake LLM, настоящие инструменты и временную SQLite; локальный
`.env` игнорируется, временные данные удаляются после завершения. Демонстрация
вычисляет `15 * 4`, сохраняет `60` и очищает историю, сохраняя заметку.

## 3. Telegram BotFather

1. Откройте официальный [@BotFather](https://t.me/BotFather) в Telegram.
2. Отправьте `/newbot`, задайте имя и свободный username с окончанием `bot`.
3. Сохраните выданный токен в локальном `.env` как `TELEGRAM_BOT_TOKEN`.
   Официальная инструкция: [получение токена Telegram](https://core.telegram.org/bots/tutorial#obtain-your-bot-token).
4. При желании задайте меню через `/setcommands`, выбрав своего бота:

```text
start - Знакомство с ботом
help - Команды и возможности
reset - Очистить историю диалога
```

Приложение само не меняет меню BotFather и настройки webhook.

## 4. OpenRouter

Создайте аккаунт и API-ключ на [странице ключей OpenRouter](https://openrouter.ai/settings/keys).
Запишите ключ в `OPENROUTER_API_KEY` в локальном `.env`.
[Документация аутентификации](https://openrouter.ai/docs/api_reference/authentication)
описывает работу ключей.

В примере используется `LLM_MODEL=qwen/qwen3-coder:free`. Наличие этой модели
не гарантировано: бесплатные варианты и квоты меняются. Перед запуском выберите
доступную модель с окончанием `:free` и поддержкой `tools` и `tool_choice` в
[каталоге OpenRouter](https://openrouter.ai/models).
[Описание бесплатных вариантов](https://openrouter.ai/docs/guides/routing/model-variants/free)
содержит условия и ограничения сервиса.

При старте приложение проверяет модель через `/models`: тарифы `prompt`,
`completion` и `request` должны быть нулевыми, а инструменты — поддерживаться.
Запросы содержат `provider.max_price` с нулевыми пределами,
`require_parameters=true` и `allow_fallbacks=false`.
[Параметры маршрутизации OpenRouter](https://openrouter.ai/docs/guides/routing/provider-selection)
описаны в официальной документации. При отказе проверки бот не запускается;
автоматической смены модели или платного fallback нет.

## 5. Локальный .env

Создайте файл, не перезаписывая существующий:

```bash
[ -f .env ] || cp .env.example .env
chmod 600 .env
```

Откройте `.env` в локальном редакторе и заполните две пустые строки:

```dotenv
TELEGRAM_BOT_TOKEN=
OPENROUTER_API_KEY=
```

Это имена настроек, а не рабочие значения. Вставьте свои ключи только в локальный
файл. `.env.example` должен оставаться без ключей. Не помещайте токены в команды,
скриншоты, GitHub issues, README или коммиты.

Для московского времени оставьте:

```dotenv
DEFAULT_TIMEZONE=Europe/Moscow
DATABASE_PATH=data/profilabych.sqlite3
LLM_MODEL=qwen/qwen3-coder:free
```

Повторите `--check` после редактирования. Запускайте команды из корня проекта:
`.env` и относительный путь SQLite отсчитываются от текущего каталога.
Переменные окружения имеют приоритет над `.env`; неизвестные поля `.env`
считаются ошибкой.

## 6. Запуск и проверка Telegram

```bash
.venv/bin/python -m profilabych --telegram
```

После проверки OpenRouter начинается long polling. Найдите созданного бота
в Telegram и отправьте `/start`, затем попробуйте:

```text
Посчитай (15 + 5) * 3
Че по времени?
Сколько сейчас времени в Токио?
Который час?
Сохрани заметку: проверить релиз в пятницу
Покажи мои заметки
```

После запроса про Токио вопрос без города снова должен использовать Москву.
`/help` показывает возможности. `/reset` удаляет историю текущего чата;
сохранённые заметки остаются. Остановка — **Ctrl+C**.

На один токен запускайте один polling-процесс. Для постоянной работы нужен
постоянно включённый компьютер или сервер. Бот работает в личных чатах с любым
человеком, который ему написал; списка разрешённых пользователей в v0.1.0 нет.

## CLI

Для локального диалога нужен только `OPENROUTER_API_KEY`:

```bash
.venv/bin/python -m profilabych
```

Команды: `/reset` — очистить историю, `/exit` — выйти. CLI использует локальные
`user_id=1`, `chat_id=0`; параметры `--user-id` и `--chat-id` предназначены для
локальной проверки и не являются аутентификацией.

## Тесты и качество кода

```bash
.venv/bin/python -m pip install --require-hashes -r requirements-dev.txt
.venv/bin/python -m pytest
.venv/bin/python -m ruff check .
.venv/bin/python -m ruff format --check .
.venv/bin/python -m mypy src
.venv/bin/python -m pip check
```

Тесты используют временную SQLite, HTTP MockTransport и Telegram mock session;
реальные ключи и внешние API не требуются. Они проверяют инструменты, изоляцию
данных, цикл агента, обработку ошибок, часовые пояса, форматирование и остановку
Telegram. Проверки релиза описаны в [отчёте подготовки v0.1.0](docs/release-preparation.md).

## Данные и безопасность

`.env`, окружения Python, SQLite и служебные файлы БД, логи, кеши и сборочные
артефакты исключены из Git. Новый запуск создаёт собственную БД; личные данные
разработчика не входят в релиз.

Тексты сообщений, история и заметки хранятся локально. Для ответа часть диалога
и результаты инструментов передаются OpenRouter и выбранному провайдеру модели.
JSON-логи могут содержать ограниченные фрагменты сообщений и заметок, даже при
маскировании ключей. Ограничьте доступ к БД и логам и не публикуйте их.

Для резервной копии остановите процесс и скопируйте `DATABASE_PATH` в закрытое
хранилище. Встроенного экспорта или удаления всех заметок в этой версии нет.
При утечке ключа отзовите его в BotFather/OpenRouter и замените локальное значение.
Удаление ключа из последнего файла Git не удаляет его из старых коммитов.

## Частые проблемы

| Симптом | Что проверить |
| --- | --- |
| `Добавьте OPENROUTER_API_KEY…` | Ключ заполнен в `.env`, запуск из корня проекта |
| `Некорректный формат TELEGRAM_BOT_TOKEN` | Использован полный токен BotFather |
| `configuration_invalid` | Имя поля в событии лога; значения не выводятся. Проверьте `.env` и IANA timezone |
| Модель недоступна / не поддерживает инструменты | Доступный бесплатный ID в каталоге OpenRouter; поменяйте `LLM_MODEL` |
| «Сервис временно недоступен…» | Квоты бесплатной модели, сеть, ключ, доступность OpenRouter; повторите позже |
| Telegram conflict | Остановите второй polling-процесс с тем же токеном |
| Polling не работает после другого хостинга | Проверьте ранее настроенный webhook. Приложение его автоматически не удаляет |
| Ошибка доступа к SQLite | Каталог `DATABASE_PATH` доступен для записи |
| Бот молчит в группе / на редактирование | Поддерживаются новые сообщения людей в личных чатах |

## Архитектура и ограничения

`main.py` собирает зависимости. Telegram и CLI передают запрос одному Agent Core;
ядро управляет историей и инструментами через отдельные контракты. Адаптер
OpenRouter отвечает за HTTP, SQLite — за хранение. Ядро не зависит от aiogram/httpx.
Подробности — [архитектура](docs/architecture.md).

```text
src/profilabych/
├── agent/                 # диалог и цикл инструментов
├── interfaces/            # Telegram и CLI
├── llm/                   # контракт и OpenRouter
├── storage/               # SQLite, история и заметки
├── tools/                 # реестр и четыре инструмента
├── config.py              # проверка настроек
├── timezones.py           # часовые пояса и отображение дат
└── main.py                # сборка и запуск
```

Дедупликация Telegram и блокировки пользователя действуют в одном процессе.
После перезапуска возможна повторная обработка; гарантий exactly-once нет.
Инструмент может успеть сохранить заметку до ошибки модели или отправки ответа.
Развёртывание в нескольких процессах не проверено.

## Docker

В репозитории сохранён существующий `Dockerfile`. Команды Docker будут приведены
только после подтверждённой сборки и проверки запуска образа. До этого используйте
проверенную установку Python выше; текущий статус указан в отчёте подготовки.
